# 任务 02：个人商店牌子

- 状态：`可直接实现`
- 优先级：高
- 依赖：`任务01-个人商店一期视图.md`

## 目标

为“个人商店”补一个稳定的牌子入口，使玩家可以通过右键牌子直接打开店主的个人商店页面。

## 本期范围

- 支持通过写牌内容创建“个人商店牌子”
- 支持牌子绑定到创建者本人
- 支持右键牌子打开店主个人商店
- 支持牌子数据持久化，重启后仍可识别
- 支持牌子与其支撑方块的基础保护
- 支持店主本人或管理员移除牌子
- 兼容普通牌子交互抢占，尽量避免被编辑型插件先吃掉右键

## 明确不做

- 不做“管理员替他人代绑牌子”
- 不做 WorldGuard / CMI / Residence 等插件的深度适配
- 不做牌子跨服同步
- 不做最近访问店铺、界面搜索跳转
- 不做新的数据库表

## 强制规格

### 1. 创建方式

- 采用“写牌创建”，不新增额外绑定命令
- 玩家放置牌子并编辑时：
  - 第一行写 `"[个人商店]"` 或 `"[gmarketshop]"` 视为创建请求
- 只有满足以下条件才允许创建：
  - `personal-shop.enabled=true`
  - 玩家拥有 `gensoumarket.personal.sign.create` 权限，或拥有管理员权限
- 普通玩家创建的牌子只允许绑定自己
- 本期管理员也默认绑定自己，不处理“代他人创建”的额外语法

### 2. 创建成功后的牌面

- 创建成功后，由插件统一重写牌面为：
  1. `&6[个人商店]`
  2. `&f<店主名>`
  3. `&7右键打开`
  4. 空行
- 若创建失败：
  - 不写入绑定数据
  - 发送明确失败提示

### 3. 持久化方式

- 使用独立 YAML 文件：`personal-shop-signs.yml`
- 不改数据库表，不接入现有 market / shop / recycle 表
- 建议存储结构：
  - 键：`<world>:<x>:<y>:<z>`
  - 值：
    - `owner-uuid`
    - `owner-name`
    - `created-at`
- 启动时加载到内存映射
- 创建、删除时同步更新内存，并保存到该 YAML 文件

### 4. 交互规则

- 使用 `PlayerInteractEvent`
- 事件建议：
  - `EventPriority.HIGHEST`
  - `ignoreCancelled = false`
- 当玩家右键一个已登记的个人商店牌子时：
  - 优先拦截普通牌子编辑逻辑
  - `event.setCancelled(true)`
  - 打开该店主的个人商店
- 打开商店时继续复用现有 `/gmarket personal <玩家>` 的加载逻辑，不另做一套数据来源
- 若店主当前无在售物品：
  - 复用现有个人商店无货提示
  - 不应抛异常

### 5. 保护规则

- 被保护对象不是只有牌子方块本身，还包括“牌子的支撑方块”
- 需要覆盖的最小保护范围：
  - 牌子方块自身
  - 若是墙牌，则保护其附着的方块
  - 若是立式牌，则保护其下方支撑方块
- 只有以下身份可以破坏该牌子或其支撑方块：
  - 牌子主人
  - 拥有管理员权限的玩家
- 普通玩家尝试破坏时：
  - 取消事件
  - 发送“无权破坏该商店牌子”之类的提示

### 6. 删除与解绑规则

- 牌子主人或管理员破坏牌子时：
  - 先移除持久化绑定
  - 再允许方块正常被破坏
- 牌子主人或管理员破坏支撑方块时：
  - 同样先移除绑定
  - 再允许破坏
- 如果牌子因为意外原因已经不存在，但存档里还有记录：
  - 在下一次交互、加载校验或相关破坏事件中做惰性清理
  - 不要求额外写全图扫描器

### 7. 爆炸与推动保护

- 至少处理以下事件：
  - `BlockExplodeEvent`
  - `EntityExplodeEvent`
  - `BlockPistonExtendEvent`
  - `BlockPistonRetractEvent`
- 行为要求：
  - 若事件涉及牌子方块或其支撑方块，应阻止该牌子被爆炸或活塞破坏/推动
  - 推荐做法是从受影响方块列表中移除这些方块，而不是整场事件直接取消

### 8. 模块关闭时的行为

- `personal-shop.enabled=false` 时：
  - 不允许新建个人商店牌子
  - 已存在牌子仍保持保护，不因模块关闭而变成普通可破坏方块
  - 玩家右键时提示“个人商店功能未启用”
- 不要把“关闭入口”误实现成“历史牌子数据失效”

## 建议实现结构

- 建议新增一个小型专用服务或仓库类，负责：
  - 加载牌子映射
  - 保存牌子映射
  - 查询某个方块是否为注册牌子或其支撑方块
- 事件监听建议单独放一个监听器，不要把这套逻辑硬塞进现有 `PlayerListener`

## 权限建议

- 新增：
  - `gensoumarket.personal.sign.create`
- 管理员仍可复用现有：
  - `gensoumarket.admin`

## 验收标准

- 玩家可通过写牌第一行创建个人商店牌子
- 创建后牌面会被插件统一改写
- 右键牌子能稳定打开店主的个人商店
- 店主无货时只显示正常提示，不报错
- 重启服务器后牌子仍可识别
- 非店主、非管理员不能破坏牌子或其支撑方块
- 爆炸和活塞不会把牌子或其支撑方块弄丢
- `personal-shop.enabled=false` 时，旧牌子仍受保护，但不能继续作为可用入口

## 备注

- 这一版的目标是“可稳定落地的个人商店入口”，不是完整牌子生态系统
- 实现时应优先保证数据不丢、牌子不乱绑、权限不穿透
