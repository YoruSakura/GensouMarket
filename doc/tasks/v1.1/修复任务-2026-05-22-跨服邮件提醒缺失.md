## 修复目标

修复后必须满足：

1. 任意运行时邮件写入成功后，如果目标玩家在线于任意子服，应收到即时邮件提醒。
2. `mail.enabled=false` 只能隐藏入口/帮助，不得阻止邮件提醒和 `/gmarket collect`。
3. 目标玩家离线时不需要即时提醒，但玩家上线后仍应由现有 join 检查提示待领取邮件。
4. 不产生重复资产，不重复写邮件。
5. 尽量避免同一封邮件在同一玩家在线时出现多次重复提醒。

## 建议实现方向

优先做小范围增量修复，不重构整个邮箱系统。

推荐方案：

1. 抽出或补齐一个统一的“保存邮件后通知”路径，避免散落的 `storage.saveMail(...)` 漏发跨服提醒。
2. 每次邮件保存成功后：
   - 保留现有 `publishMailCreated(...)` 行为，兼容已有广播刷新/提醒逻辑。
   - 如果目标玩家不在当前服且 `cluster.enabled=true`，额外走 `requestPlayerNotify(targetUuid, message)` 做定向提醒。
   - 如果目标玩家在当前服，主线程直接发送本地提醒。
3. 统一提醒文案建议使用：

```text
&e你有新的待领取物品/金币！使用 &a/gmarket collect &e领取
```

4. 对已有带具体原因的 `notifyMessage` 路径，可以继续发送具体原因；没有具体文案时使用统一默认文案。
5. 不要把本次修复扩大到 QuickShop 或回流出售算法。

注意：

- `PLAYER_NOTIFY` 是定向路由，更适合“某个玩家在线于哪台子服就发到哪台子服”的场景。
- 如果选择把 Velocity 端 `MAIL_CREATED` 从广播改成定向消息，需要同时确认不会破坏原设计中“其他服收到 MAIL_CREATED 后刷新/提示”的行为；改动前应评估兼容性。

## 第一次修复记录（已废弃，仅作审计留存）

> 这一版修复后来确认存在重复提醒风险，且不能覆盖源服无人在线时 Plugin Messaging 无法发送的问题。最终以“二次修正记录”为准。

### 根因定位

通过 `rg` 搜索所有 `storage.saveMail()`、`saveMailAsync()`、`publishMailCreated()`、`requestPlayerNotify()` 调用点，共发现 **15 处** `storage.saveMail()` 路径。

问题分为两类：

1. **`saveMailAsync()` 统一入口**（MarketManager、AuctionManager 各一个）：当调用方传入 `notifyMessage=null` 时，只发 `publishMailCreated`（广播），不发 `requestPlayerNotify`（定向路由）。大量调用方传 `null`（如市场售出给卖家写邮箱、拍卖结束给卖家/赢家写邮箱等），导致这些路径丧失定向通知能力。

2. **直接 `storage.saveMail()` + `publishMailCreated()` 路径**：完全没有 `requestPlayerNotify`。覆盖：市场下架离线邮箱、买家离线邮箱、拍卖竞价退款邮箱（跨服回退 + 非跨服）、拍卖结束邮箱（卖家/赢家/无人竞拍）、拍卖取消邮箱（竞拍者退款 + 卖家退物）。

3. **`cancelAllActiveAuctions()`（启动时取消遗留拍卖）**：两处 `storage.saveMail()` 连 `publishMailCreated` 都没有，完全无跨服通知。

`publishMailCreated` 是广播消息，Velocity 转发给所有非源服后由 `handleMailCreated` 检查目标玩家是否在本服。理论上能工作，但不如 `requestPlayerNotify`（定向路由，Velocity 精确找到目标玩家所在服投递）可靠。实际测试中广播路径未能送达提醒，补充定向路由是最小影响的修复。

## 二次修正记录（2026-05-22 Codex 执行）

### 对上一次修复记录的纠正

上一次修复存在两个问题：

1. `publishMailCreated` 与额外补发的 `requestPlayerNotify` 都依赖 `ProxyBridge.send()`，而 Paper 插件消息发送要求源服至少有 1 个在线玩家。源服无人在线时，两条消息都会发不出去，不能覆盖定时拍卖结算等空服写邮箱场景。
2. 同一封邮件同时走 `MAIL_CREATED` 广播提醒和 `PLAYER_NOTIFY` 定向提醒，目标玩家在线于异服时可能收到重复聊天提示。

### 本次修正

仅改 Plugin 端，Velocity 端未改动。

新增：

- `GensouMarket-plugin/src/main/java/net/scarletphantasy/gensouMarket/mail/MailNotificationService.java`
  - 集群模式下每 5 秒轮询本服在线玩家的未领取邮箱 ID。
  - 只在发现新增未领取邮件 ID 时发送一次默认提醒。
  - 该兜底不依赖源服是否有在线玩家，适合源服空服但已写入共享 MySQL 的场景。
  - 收到 `MAIL_CREATED` 后会短时间抑制轮询重复提醒。

调整：

- `GensouMarket.java`
  - 集群模式启用时启动 `MailNotificationService`。
  - 插件关闭时停止该服务。
- `PlayerListener.java`
  - 玩家加入时读取现有邮件后，把当前邮件 ID 记录为已知状态。
  - 玩家退出时清理该玩家的轮询状态。
- `RemoteActionHandler.java`
  - 收到 `MAIL_CREATED` 后记录外部即时提醒，并异步刷新该玩家的已知邮件 ID。
- `CommandManager.java`
  - `/gmarket collect` 领取后刷新该玩家的已知邮件 ID，避免领取后轮询状态滞后。
- `MarketManager.java` / `AuctionManager.java`
  - 撤回上一次补加在邮件保存路径上的 `requestPlayerNotify(...)`。
  - 保留 `publishMailCreated(...)` 作为有在线源玩家时的即时跨服提醒。
  - 保留启动取消遗留拍卖时补上的 `publishMailCreated(...)`；若启动阶段无玩家导致插件消息发不出，由轮询/上线提醒兜底。
