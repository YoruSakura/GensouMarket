# 任务 05：服务器商店双模式

- 状态：`可直接实现`
- 优先级：高
- 依赖：无

## 目标

让服务器商店支持两种明确模式：

- 固定售价模式（`fixed`）：管理员固定出售
- 回流出售模式（`recycled`）：回收回流出售

本期要求把规则定死到足够能直接实现，不再停留在概念层。

## 本期范围

- 商店项按“每个商品”配置模式，不做全局二选一
- 固定售价模式（`fixed`）支持：
  - 固定价格
  - 无限库存
  - 有限库存
- 回流出售模式（`recycled`）支持：
  - 从回收池出货
  - 按当前回收价乘倍率计算售价
  - 有库存才可卖
- 扩展现有 `ShopItem` / `RecycleItem` / `StorageProvider` 持久化结构
- 更新商店界面物品说明与购买校验
- 补一个最小可用的固定库存管理命令

## 明确不做

- 不做跨服共享商店库存
- 不做 QuickShop 联动
- 不做基于 NBT 数据 / 附魔 / 自定义物品元数据的库存池
- 不做按玩家维度的限购
- 不做“自动把回收物品生成新的商店条目”

## 强制规格

### 1. 模式粒度

- 模式粒度为“每个商店商品”
- `shop.yml` 中每个商品都必须有 `mode`
- 可选值仅有：
  - `fixed`
  - `recycled`

### 2. 固定售价模式（`fixed`）规则

- 固定售价模式（`fixed`）商品必须有：
  - `buy-price`
  - `stock-mode`
- `stock-mode` 可选值：
  - `unlimited`
  - `limited`

#### 固定售价 + 无限库存（`fixed + unlimited`）

- 行为与当前商店最接近
- 永不扣减库存
- 商店界面不显示剩余库存，可标注“无限库存”

#### 固定售价 + 有限库存（`fixed + limited`）

- 需要持久化当前可售库存
- 配置项使用 `initial-stock`
- `initial-stock` 只在“该商品没有历史持久化库存”时作为初始值使用
- 后续库存变动以持久化数据为准，不能在每次重载（`reload`）时被配置覆盖回去
- 玩家购买成功后扣减 `available-stock`
- 库存为 0 时显示缺货，不能购买

### 3. 回流出售模式（`recycled`）规则

- 回流出售模式（`recycled`）商品必须有：
  - `recycle-source`
  - `sell-multiplier`
- `recycle-source` 指向 `recycle.yml` 中某个 `RecycleItem` 的 id
- 回流出售模式（`recycled`）商品的库存来源于该 `RecycleItem` 的“回流库存”
- 回流出售模式（`recycled`）本质上总是有限库存，不再额外配置 `stock-mode`

#### 售价公式

- 当前售价 = 当前回收价 × `sell-multiplier`
- 这里的“当前回收价”沿用现有回收系统价格：
  - `baseRecyclePrice`
  - `recycleMultiplier`
  - `marketFluctuation`
- 最终结果保留两位小数
- 若结果小于 `0.01`，按 `0.01` 处理，避免出现 0 价或负价

#### 库存来源

- `RecycleItem` 新增持久化字段：
  - `recycledStock`
- 玩家成功回收某物品后：
  - 在现有回收逻辑成功完成后，再把对应 `RecycleItem.recycledStock += 回收数量`
- 玩家购买回流出售模式（`recycled`）商品后：
  - 对应 `RecycleItem.recycledStock -= 购买数量`
- 若 `recycledStock <= 0`：
  - 商店商品显示缺货
  - 不允许购买

### 4. 回收与商店之间的关系

- 回收行为只负责把数量注入回流库存池
- 不要求自动创建商店商品
- 只有 `shop.yml` 中显式配置为回流出售模式（`recycled`）的商品，才会消费该库存池
- 若某个 `recycle-source` 存在库存，但没有对应的商店商品配置：
  - 库存继续保留
  - 不做自动展示

### 5. 界面显示规则

- 商店界面继续显示所有已配置商品，不做“缺货即隐藏”
- 物品说明规则：
  - 固定售价 + 无限库存（`fixed + unlimited`）：显示固定价格、无限库存
  - 固定售价 + 有限库存（`fixed + limited`）：显示固定价格、剩余库存
  - 回流出售模式（`recycled`）：显示当前动态售价、剩余回流库存、回流来源
- 库存为 0 时：
  - 物品说明明确显示“缺货”
  - 点击购买时直接提示缺货

### 6. 购买流程规则

- 购买时先判断模式与库存，再判断余额
- 任一模式库存不足时都不能继续扣款
- 只有在库存与余额都满足后才允许购买
- 扣款成功、物品发放成功后，再更新库存与统计
- 固定售价 + 有限库存（`fixed + limited`）更新 `ShopItem.availableStock`
- 回流出售模式（`recycled`）更新 `RecycleItem.recycledStock`

### 7. 管理员命令约束

#### 保留现有命令语义

- `/gmarket shop add ...`
  - 本期仍只创建固定售价 + 无限库存（`fixed + unlimited`）商品
- `/gmarket shop setprice <itemId> <buyPrice>`
  - 仅允许用于固定售价模式（`fixed`）
  - 若目标商品是回流出售模式（`recycled`），应直接提示“回流商品价格由回收价和倍率决定，不能直接 `setprice`”

#### 新增最小库存命令

- 新增：
  - `/gmarket shop setstock <itemId> <amount>`
- 语义：
  - 仅适用于固定售价 + 有限库存（`fixed + limited`）
  - 直接把 `available-stock` 设为指定值
  - 不适用于固定售价 + 无限库存（`fixed + unlimited`）
  - 不适用于回流出售模式（`recycled`）
- `amount < 0` 时按非法输入处理

### 8. 配置格式

`shop.yml` 目标格式以此为准：

```yml
items:
  diamond:
    material: DIAMOND
    mode: fixed
    buy-price: 1000.0
    stock-mode: unlimited

  iron_ingot:
    material: IRON_INGOT
    mode: fixed
    buy-price: 80.0
    stock-mode: limited
    initial-stock: 256

  cobblestone_recycled:
    material: COBBLESTONE
    mode: recycled
    recycle-source: cobblestone
    sell-multiplier: 1.35
```

### 9. 数据模型扩展

建议最小扩展如下。

#### `ShopItem`

- 新增：
  - `mode`
  - `stockMode`
  - `availableStock`
  - `recycleSourceId`
  - `sellMultiplier`

#### `RecycleItem`

- 新增：
  - `recycledStock`

### 10. 持久化要求

- 不新开独立库存池表，优先复用现有 shop / recycle 持久化结构扩字段
- `MySQLStorage` / `SQLiteStorage` / `YamlStorage` 都必须支持新字段
- 旧数据兼容默认值：
  - 老的 `ShopItem` 一律按固定售价 + 无限库存（`fixed + unlimited`）解释
  - 老的 `RecycleItem.recycledStock` 默认 `0`
- 重载（`reload`）后不能把已持久化的有限库存覆盖回配置初始值

## 推荐实现切分

建议按以下顺序实现：

1. 先扩模型与配置读取
2. 再扩三种存储实现
3. 再改 `ShopManager` / `RecycleManager` 的业务流
4. 最后补界面物品说明与管理员命令

## 验收标准

- 固定售价 + 无限库存（`fixed + unlimited`）商品行为保持与当前版本兼容
- 固定售价 + 有限库存（`fixed + limited`）商品能正确显示库存、扣减库存、缺货阻止购买
- 回流出售模式（`recycled`）商品只有在回流库存大于 0 时才可购买
- 回收物品后，对应回流库存会增加
- 购买回流出售模式（`recycled`）商品后，对应回流库存会减少
- 重载（`reload`）后有限库存和回流库存不会丢失
- `setprice` 不会错误作用到回流出售模式（`recycled`）商品
- `/gmarket shop setstock` 可正确修改固定售价 + 有限库存（`fixed + limited`）库存

## 备注

- 这一版的重点是先把“双模式”做成一套稳定、能解释、能持久化的规则
- 不要在本任务里顺手扩成“跨服共享库存”或“自动生成商品目录”
